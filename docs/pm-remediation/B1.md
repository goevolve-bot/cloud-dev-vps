## Background you need

The stack runs under **rootless Docker as the `pm` system user** (see
`roles/pm/tasks/base.yml` §8, `pm-compose.service.j2`). This matters for every
mount decision below: inside a rootless daemon, container uid 0 maps to the host
`pm` uid and container gid 0 maps to the host `pm` primary group (which is `pm`).
`app/server/Dockerfile` sets no `USER`, so the pm process runs as container root
→ host `pm:pm`. Project `.pm/` trees are mode 2770 owned `pm-<name>:pm`. So a
plain bind mount should be readable/writable **provided the container stays root
and the mapping holds** — verify the reasoning as you go and comment it.

`pm-projectctl`'s `DEFAULT_CONFIG` (app/scripts/pm-projectctl:52) fixes these
host paths, which the container must match:

```
socket_path  /srv/pm/projectctl.sock     (root:pm, connected to by pm)
runners_dir  /srv/pm/runners             (one dir per project, socket inside)
state_dir    /srv/pm/projects
work_subdir  work                        → clone at /home/pm-<name>/work/<repo>
runner_exec  ["/usr/bin/node", "/srv/pm/app/runner/dist/index.js"]
```

## Issues to fix

### 1.1 — The pm container has no volumes at all (review §3.3)

`app/compose.yaml`'s `pm:` service declares `build`, `restart`, `expose`,
`environment` and **no `volumes`**. Consequences, all currently live:

- `PM_RUNNERS_DIR` (`/srv/pm/runners`) is empty inside the container, so every
  project reads as `disconnected` and `runners.client()` is always `undefined`.
- `callProjectctl` connects to `/srv/pm/projectctl.sock`, which does not exist in
  the container — every lifecycle and credential call returns `connection_error`.
- `project.repo_dir` points at `/home/pm-<name>/work/<repo>` on the host; the
  container cannot see it, so `createTask` / `addComment` / `addRunOutcome` all
  fail with `ENOENT`, despite the on-host permission model being built precisely
  to make those writes work.
- `PM_DB_PATH` defaults to `/var/lib/pm/pm.sqlite3` **inside the image**, so the
  database and all run history are lost on every container recreate.
- `PM_DATA_DIR` is never set, so JSONL logs and copied artifacts land in the
  container's `/repo/server` (`queue.ts` ~line 254 and ~327). Ansible creates
  `/srv/pm/data` and `/srv/pm/data/runs` and then never uses them.

**Fix:** give `pm:` the mounts it needs and set the matching env vars.

- `/srv/pm/runners` → read-only is correct (pm only connects, never creates).
- `/srv/pm/projectctl.sock` → read-write bind of the socket file. Note the socket
  is systemd-socket-activated; if binding the file directly proves fragile
  because the socket is recreated, bind `/srv/pm` instead and comment why.
- `/srv/pm/data` → rw, and set `PM_DATA_DIR=/srv/pm/data` and
  `PM_DB_PATH=/srv/pm/data/pm.sqlite3`.
- Project homes: pm needs `/home/pm-*/work/<repo>/.pm/`. A single `/home` mount is
  the blunt option; consider whether a narrower mount is achievable given projects
  are created dynamically after the stack is already running (a mount added at
  compose time cannot know about a project created later — this is the crux, and
  a parent-directory mount is probably the only workable answer). Decide, and
  write a comment explaining the choice.
- Ensure `roles/pm/tasks/base.yml` §5 creates every directory you mount, with the
  ownership the container needs.

### 1.2 — The SPA is never served (review §3.2)

`app/server/Dockerfile` copies only `core` and `server`; `app.ts` registers no
static handler; `app/nginx/nginx.conf` proxies `location /` to `pm:3000`. The
built `web/dist` exists only as a local artifact. Browsing to the origin returns
Fastify's 404 JSON.

**Fix:**
- Build `web/` in `app/server/Dockerfile` (the build context is already the
  workspace root, and `web/package.json` is already copied for the install step —
  but the install is `--filter @pm/server...`, so widen it).
- Add `@fastify/static` in `app.ts` serving the built `web/dist`, with an SPA
  fallback so client-side routes (`/specs`, `/adrs`, task URLs) resolve to
  `index.html` — without shadowing `/api/*`.
- Confirm the nginx `location /` proxy is then correct, in **both**
  `app/nginx/nginx.conf` and `roles/pm/templates/nginx.conf.j2` (they must not
  drift — check whether one should simply be generated from the other).

### 1.3 — The runner binary is never deployed to the host (not in the review)

`pm-projectctl`'s `install_runner` renders a systemd user unit whose `ExecStart`
is `/usr/bin/node /srv/pm/app/runner/dist/index.js`. But:

- `roles/pm/tasks/base.yml` syncs the app to `pm_app_dest` = **`/opt/pm/app`**,
  not `/srv/pm/app`; and
- the sync excludes `*/dist`, and nothing ever runs `pnpm --filter @pm/runner build`
  on the host.

So the file `ExecStart` points at does not exist, and **every project's runner
would fail to start** — which also means pm never sees a runner socket even after
1.1 is fixed. This is a blocker equal in weight to the other three.

**Fix:** decide where the runner lives and make the three places agree —
`DEFAULT_CONFIG["runner_exec"]`, whatever Ansible deploys, and `/etc/pm-projectctl.conf`
if you choose to use the config override instead of changing the default. Add an
Ansible task that builds `@pm/runner` (and its `@pm/core` dependency) and places
`dist/` plus its runtime `node_modules` where the unit expects them. Node must
also be on the host at `/usr/bin/node` — check whether anything guarantees that
and add it if not.

### 1.4 — The Ansible htpasswd never reaches nginx (review §5.3)

`roles/pm/tasks/nginx_tls.yml` writes the generated file to
`{{ pm_app_dest }}/auth/htpasswd`, but `compose.yaml` mounts the **named volume**
`auth:` into nginx and populates it from the `auth-init` one-shot, whose defaults
are `admin` / `changeme`. A production deploy therefore ends up with the hardcoded
dev password protecting the UI and the vaulted one unused.

**Fix:** make the file Ansible writes the one nginx actually reads. A bind mount of
the app-tree `auth/` directory is the straightforward answer; keep `auth-init` (or
an equivalent) working for local dev where Ansible hasn't run, but never let it
overwrite a file Ansible placed.

Related: `group_vars/all.yml` ships `pm_auth_password: changeme` in plaintext.
Replace it with a vault-encrypted value or, if you cannot vault it in this session,
remove the default entirely so the play fails loudly rather than deploying a known
password. State which you did.

### 1.5 — `ip_unprivileged_port_start` is 80, should be 443 (review §5.4)

`roles/pm/defaults/main.yml` sets `pm_sysctl_unprivileged_port_start: 80`, which
opens every port ≥ 80 to unprivileged binds. There is deliberately no `:80`
listener in the stack. (`docs/pm-task-breakdown.md` says 80 and
`docs/pm-system-plan.md` says 443 — 443 is the tighter and stated-elsewhere intent;
go with 443 and fix the stale line in the task breakdown.)
